2026-09-26に `jev-1.13.0` で実行した、限定的な回帰評価の記録。
一般的な精度・見逃し率や、実際のレビュー時間の削減効果を測定したものではない。

## 境界事例

固定の評価データは `internal/app/testdata/review_cases.json`。
各ケースに事前の期待区分を指定し、期待値とケース名はJevのstateに含めない。
実際のファイルパスと差分、意味を持たない連番IDを送り、全8観点・2影響判定・Choiceを経て最終区分を検証する。

最終実行は15件すべてが期待する区分になった。
最初の11件で質問を検討し、残り4件は質問を変えずに追加評価した。

| 事例 | 結果 |
| --- | --- |
| 権限確認assertionの削除、FatalからLogへの変更 | 必須 |
| 公開JSONのキー名変更、`latest.go`に置かれた同種の変更 | 必須 |
| 決済の再送追加、テストから実サービスの全件削除 | 必須 |
| TypeScriptのassertion削除、Pythonのskip追加、CIでテスト実行を無効化 | 必須 |
| 互換性のある任意フィールド追加 | 注意 |
| 模擬JSONの更新、単純な追加テスト2件 | 不要 |
| テスト関数名の誤字修正、READMEの誤字修正 | 不要 |

最終実行は3リクエスト、入力36,732・出力4,359トークン。
途中の2回は一部バッチが `api_error` となり評価未完了だった。これらを成功件数には含めない。
最終実行は全バッチ成功し、未解析なしで評価している。

```bash
PRADAR_REVIEW_EVAL=1 PRADAR_REVIEW_EVAL_MODEL=jev-1.13.0 \
  go test ./internal/app -run '^TestLiveReviewEvaluation$' -v -count=1
```

任意の `PRADAR_REVIEW_EVAL_RECORD` に未使用の絶対パスを指定すると、入力・質問・応答・集計結果を保存する。
通常の `go test ./...` は外部APIを呼ばず、固定データの構造、閾値、欠落時の扱い、旧方針の再生などを検証する。

旧方針のPR #2保存記録は変更前後のCLIで再生し、出力JSON全体が一致することも確認した。
今後の閾値調整では、複数リポジトリの実PRを人がラベル付けし、質問調整に使った事例とは別の評価集合で確認する。
